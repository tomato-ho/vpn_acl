# 安全模型与边界

这份文档说明系统**保护什么、不保护什么**，用于部署评估与审计沟通。

## 1. 信任边界

```
不受信                  │ 受信（本机 root）
────────────────────────┼──────────────────────────────
VPN 客户端              │ vpn-openvpn / vpn-policyd
浏览器（管理员）        │ vpn-admin
                        │ vpn-mariadb
```

- VPN 客户端**一律视为不可信**：即使客户端自行 `route add`，网关仍按策略 drop；
- 管理员浏览器通过 TLS 访问后台，会话 Cookie + CSRF Token；
- `vpn-admin`、`vpn-mariadb` 只监听 `127.0.0.1`；
- 能读 `/etc/vpn-policy`、`mariadb/data`、`/var/backups/vpn-acl` 的人等同于系统管理员。

## 2. 强制点在服务端

`push "route ..."` 只是告诉客户端“这些网段走隧道”，客户端可以绕过。真正的控制是
转发路径上的 nftables 规则：

- `allow` 规则逐包计数并放行；
- `deny` 规则逐包 drop（同时进审计集合）；
- 未授权的目标不在任何规则里，默认拒绝；
- 策略变更写 `vpn_policy_version`，在线会话原子刷新。

因此**撤回授权后，客户端发往该目标的包会立即被丢弃**，不依赖客户端配合。

## 3. 已实现的防护

| 项 | 说明 |
|---|---|
| 密码存储 | PBKDF2-SHA256（`pbkdf2-sha256$迭代$盐$哈希`） |
| 认证限流 | 同 `username+IP` 5 次/5 分钟，同 IP 20 次/5 分钟 |
| 用户枚举 | 未知用户执行 dummy PBKDF2，错误信息统一 |
| 会话 | 管理员会话 Cookie + 非 GET 请求 `X-CSRF-Token` |
| Web | CSP、HSTS、nosniff、X-Frame-Options、Referrer-Policy |
| 登录跳转 | `redirect` 只接受站内 `/` 路径 |
| 指标 | `/metrics` 仅本机 / Podman 网关 |
| 管理 socket | OpenVPN management socket 收紧为 `0660` |
| 凭据分离 | 数据库 root 与应用账号密码必须不同 |
| 审计 | 认证失败、管理员操作、访问目标、会话历史 |

## 4. 已知边界（不承诺）

| 项 | 说明 |
|---|---|
| 只管隧道流量 | split tunnel 或客户端本地直连的流量看不到、管不到 |
| `deny` 不是全网微隔离 | 客户端若能通过其他路径直达目标，网关无法阻止 |
| 反向流量不按 allow 过滤 | 撤回授权后，目标→客户端的 established/UDP 在途流量可能短暂继续；反向规则只统计 |
| 单向源地址伪造 | 共享 `tun0` 下，恶意客户端可伪造其他隧道 IP 发包，但回包归真实客户端，不构成双向越权；可能污染审计 |
| 仅 IPv4 | 不支持 IPv6 策略与审计 |
| 不记端口 | 访问审计只有目标 IP，没有端口/域名 |
| 审计是近似值 | 字节为 L3 转发字节，与 OpenVPN 总量口径不同，不能用于计费 |
| 无 WORM | 数据库账号可修改审计表；需要取证级不可篡改时应外送只写存储 |
| 单实例 | 数据库、policyd 都是单点，没有 HA |
| 无 MFA / SSO | 仅本地账号密码；无 LDAP/OIDC/SAML/TOTP |
| 无 RBAC | 所有管理员权限相同 |

## 5. 威胁模型

**在模型内：**

- 恶意或被入侵的 VPN 客户端尝试越权访问内网；
- 暴力破解 VPN 账密；
- 会话中途被撤销权限的用户继续发包；
- 管理员误操作（清空 allow 网段、改错固定 IP）。

**不在模型内：**

- 已取得宿主 root 的攻击者；
- 物理接触服务器或备份介质；
- 数据库被直接篡改（无防篡改机制）；
- 供应链攻击（OpenVPN、基础镜像、EL10 包）；
- 拒绝服务（大量扫描可占满审计集合，只告警不阻断）。

## 6. 部署建议

1. **最小暴露**：只放行 443 与 1194/udp；8080/3306 不要对外；
2. **独立主机**：不要和面向公网的其他服务共用；
3. **备份加密**：备份含私钥与数据库密码，存放位置需加密并限制访问；
4. **定期演练**：`deploy/test-restore.sh` 至少每月一次；
5. **监控告警**：`verify.sh` 每日执行，`/metrics` 接入 Prometheus；
6. **及时升级**：跟随 `CHANGELOG.md`，升级前备份。
